# `runbooks/` — 运维剧本

> 故障响应剧本。线上出事时**严格跟随**，不要临场发挥。

## 为什么需要这一层

故障响应的特点：
- **时间紧** — 没空查文档
- **压力大** — 容易做错决策
- **多人协作** — 必须有共识流程

剧本（runbook）= 把**过去事故的教训**固化成可机械执行的步骤，让 incident 处理脱离个人能力依赖。

## 与 `handbooks/` 的差异

| 类型 | 用途 | 心态 |
|------|------|------|
| handbooks/ | 日常操作 How-to | 边查边做 |
| runbooks/ | 故障响应剧本 | 严格按步骤，质疑等事后 |

## 现有文件

| 文件 | 范围 |
|------|------|
| [`incident-response.md`](incident-response.md) | 通用故障响应流程 |

按需扩展：
- `db-down.md` — 数据库不可用
- `high-latency.md` — 接口延迟突增
- `payment-failure.md` — 支付链路故障
- `data-corruption.md` — 数据损坏（最严重）

## 写法原则

1. **每个剧本对应一类故障** — 不要写"通用故障处理"这种万金油
2. **步骤编号 + 时间预算** — `Step 3 (≤2 min): 切流量到备用集群`
3. **明确决策点** — 在哪一步需要联系谁、什么情况下停止剧本上报指挥
4. **事后必须 update** — 处理完一次 incident，剧本必须修订（增补踩坑）
