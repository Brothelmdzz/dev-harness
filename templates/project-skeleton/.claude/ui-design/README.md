# `ui-design/` — 视觉层

> 告诉 AI **页面应该长什么样**。这一层不约束代码（→ `rules/`），不规定模板（→ `code-design/`），只提供视觉锚点。

## 为什么需要这一层

仅靠 PRD 文字（"列表 + 新增按钮 + 编辑弹窗"）让 AI 写前端，结果是布局可猜测但细节失控（间距、字号、空状态、loading 态都得反复调整）。

得物 *Spec Coding* 实战的解法：**直接放 HTML 高保真稿**。

## 怎么用

### 方式 1：高保真 HTML 稿（推荐）

设计师产出的 HTML 静态稿（含完整样式、占位数据）放进 `ui-design/`。AI 在 implement 阶段对照 HTML 写 React/Vue 组件，**几何位置、配色、间距严格还原**。

### 方式 2：Figma 链接 + 截图

如果设计师只给 Figma：
- 导出关键页面为 PNG，放 `ui-design/screenshots/`
- 文件 `figma-links.md` 记录每个页面的 Figma URL（供人类参考，AI 看截图）

### 方式 3：组件草图（最简）

只给 ASCII 草图也比纯文字好：

```
┌─────────────────────────────────────┐
│ 订单管理              [+ 新增订单] │
├─────────────────────────────────────┤
│ 搜索: [_______]  状态: [全部 ▼]   │
├─────────────────────────────────────┤
│ ID    │ 金额  │ 状态  │ 操作       │
│ #001  │ ¥100  │ 已支付│ [编辑][删] │
│ ...                                 │
├─────────────────────────────────────┤
│              [< 1 2 3 ... 10 >]    │
└─────────────────────────────────────┘
```

## 维护原则

1. **HTML 稿用语义化标签** — 让 AI 能 grep 到（`<table>` 而非 `<div role="table">`）
2. **占位数据用真实业务感** — `订单 #ABC-001` 而非 `Item 1`
3. **保持可静态打开** — `python -m http.server` 能跑，不依赖任何 build
