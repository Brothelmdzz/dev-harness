# 共享工作约定

## 事实入口

Git 保存代码与差异；既有任务平台保存目标、责任和状态；设计/ADR 保存决定；CI、制品及部署系统保存验证事实。地图指向这些来源，按任务读取，复用已有材料。

项目约定决定集成路线和完成标准，个人环境偏好不覆盖它们。工具和凭证使用各自环境的已有机制；共享资料只记录凭证取得方式，个人配置遵循项目忽略规则，真实密钥不进入代码、任务或交接。配置与引用资料不新增操作授权，实际执行遵循宿主和用户有效指令。

## 接续与归属

从一项工作的主入口能找到当前目标、负责人、有效决定、执行范围、候选、证据和下一动作。内容放在既有任务、MR 或交接位置；已有记录正确就引用，不为每轮工作另建表单。

按项目机制认领并回读状态。字段更新或回读本身不保证互斥；平台能力未证实时采用团队约定分配，归属或共享接口冲突交由已有负责人协调，其他独立工作继续。Git/宿主提供工作区隔离，任务平台/宿主负责调度；保留其他人的修改。

接手、收到反馈和准备交接/集成时核对相关决定是否仍有效。新决定替代旧决定时，在原入口留下来源及受影响工作；接收者只凭可取得的项目资料继续，必要业务歧义才升级，私人聊天不作为唯一依据。

## 交付证据

按有效任务范围说明已实现、未实现和已实现但未验证的部分；小改动一句话即可。入口接受、任务入队或局部测试只证明对应环节，不能据此缩减原验收范围。

实现、静态检查、实际测试、合入、制品、部署和业务接纳分别取证。每个结论指向适用候选及原始回执；未运行、失败、跳过、环境不可用及未知分别说明。保留异步命令的会话/任务标识，取得最终状态后判断；中间日志和等待超时不代表结果，外层 shell 成功不覆盖内部失败。失败归因需基线或因果证据，文件未改不证明与本次无关。

复用同一候选的有效证据，只因变更、修复或实际缺口重查受影响部分。精确标识及数量优先链接机器回执；确需复写时从真实来源生成并核对输出，查不到就保留未知，不手抄猜补。

候选采用项目已有的提交、MR 或工作区标识。普通同机接续可直接使用原工作区并核对差异；跨环境传递或固定未提交评审范围时，才准备可取得的补丁/快照。基线 SHA 本身不标识未提交内容，额外打包与制品审计按项目实际要求进行。

写回前核对目标，结果不确定先查现状再重试。平台不可用时保留待同步材料，明确尚未共享；本机路径不能证明跨机器可达。
