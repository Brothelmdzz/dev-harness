# 变更检查

读取项目地图、关联任务和[共享约定](../../references/shared-work.md)。准备 MR 是作者准备；审查请求是评审，发现问题不自动授权修改代码。

确定实际 target/base/head。先确认目标分支与起点，再按实际提交范围读取完整 diff；任务可能有多次提交，不能默认 HEAD~1。普通本地检查直接读取工作区差异，保留改动归属；只有传递或固定未提交候选时，读取[未提交候选](../../references/local-candidate.md)。

## 作者准备

1. 从候选检查行为、接口、数据及运行影响。触及公共接口/共享结构、影响其他工作或集成目标时，按[变化与集成](../../references/change-and-integration.md)核对在途依赖和集成人；依赖未记录不等于没有影响。
2. 每次检查[知识维护](../../references/knowledge.md)：用现有索引与源码判断影响，按变化更新必要的业务、架构、接口或运行说明。没有相关变化就说明无需更新。
3. 按共享约定执行项目既有验证并核对完成回执、适用范围与失败归因；每项结果关联实际候选、环境及原始证据。
4. 准备 MR 材料：目标与原因、关联任务、候选、影响、知识更新、范围覆盖、验证、集成前提和剩余事项。以原任务检查交付范围，按当前授权写回；未获写回授权或无法访问时留下本地可审查材料。

## 独立审查

1. 固定候选，分别检查需求符合性、工程约定及关键回归风险，按需调用现成专项能力。
2. 问题提供位置、触发条件、影响与证据；疑点标为待验证。索引关联、测试存在和审查无发现都不等于行为测试通过。
3. 报告真实范围与限制。head、关键决定或依赖改变时，旧报告保留原适用范围，重新检查受影响结论。独立性不足时标为作者自检；人数投票不替代问题核验。

报告合入状态时按[变化与集成](../../references/change-and-integration.md)核对真实集成范围；精确标识和数量按共享约定核对原始回执。结果标明模式。通过检查不自动授权合并、发布或部署。
