# 工作交接

1. 读取项目地图、当前任务及[共享约定](../../references/shared-work.md)，确认接收方的下一项工作。核对真实候选、有效决定与原始验证材料。
2. 在项目指定位置留下足以执行下一动作的简短交接：当前目标、可取得的候选、有效决定及来源、证据与尚缺项。已有任务/MR 足够就引用，只补缺失或变化的内容；不强制另写文档。普通同机接续使用原工作区；跨环境传递或固定未提交候选时，读取[未提交候选](../../references/local-candidate.md)。本地路径只能供同机接手，跨机器须有获授权的可达来源。
3. 按接收方补足内容：开发需要入口、接口约束和依赖；测试需要输入、预期、候选和运行方法；运维需要制品标识、环境、检查与恢复方法。下一步区分已确认任务与待决定建议；项目采用约定式分配时，不擅自增加实现锁服务的任务。热补丁尚未进入镜像时明确指出，不能称为可重复部署完成。
4. 涉及方向变化、其他在途工作或报告已合入时，按[变化与集成](../../references/change-and-integration.md)核对影响、实际集成范围和剩余工作；资料由谁确认与何时有效要可追溯。凭证只给取得方式，不转存私人对话或真实密钥。
5. 按已有授权写回并核对可达性；不确定外部写入是否成功时先查状态再重试。尚未共享时明确标记并保留材料，不清理原候选或证据。

接收者恢复时先核对仓库、候选和有效决定，按原始来源判断交接后是否又有变化；交接摘要不覆盖更新的决定。只重查受影响部分，普通同目标接续沿用有效授权。缺少会改变业务结果的信息才询问，并把补充记录到共享入口。

作者可核对入口和接收条件，报告材料已备妥或尚缺什么；只有观察到接收者实际接续，才报告交接已验证。写完总结不等于对方已接纳或已部署。
