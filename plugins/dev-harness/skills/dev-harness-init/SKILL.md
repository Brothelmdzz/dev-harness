# 项目初始化

建立一个新参与者能找到任务、有效决定、工具和验证入口的工作地图。

1. 定位实际仓库根、分支及脏状态，读取项目现有规范和工作入口。已有等价地图就复用；既有文件与用户编辑保持原归属。
2. 按[项目地图模板](../../templates/project-map.md)从 README、任务、有效设计、CI 和运行说明确认入口。只记录已查证的约定和难以直接推断的信息；链接已有来源，未知项明确标注，不补造业务决定。
3. 按[共享约定](../../references/shared-work.md)区分团队事实与个人环境。工具、登录和网络分别查证；未检查写“未验证”，普通初始化不安装工具或首次建立代码索引。
4. 已授权初始化时最小更新地图，默认 `.dev-harness/project.md`。在现有宿主指令中去重加入：“接手、恢复、检查变更或交接本项目工作时，先读 .dev-harness/project.md，并按任务读取其引用。”使用等价地图时替换路径。只读核对请求输出建议，不写文件。保留现有指令原文，重复运行只改真实变化。
5. 检查新增本地引用和宿主入口。完成时列出地图位置、已确认能力及缺项；分别说明资料就绪、个人环境就绪和外部连通的证据。

产出是可定位的项目入口，不要求完整 PRD、全仓 Wiki、个人环境配置或新任务数据库。只询问真正影响协作结果的归属和业务歧义；其他已授权工作继续。
