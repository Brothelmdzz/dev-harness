# 接手与推进

1. 从项目 AGENTS.md/CLAUDE.md 的入口或 `.dev-harness/project.md` 读取地图，定位指定任务、有效决定和相关规范。入口缺失时先用已有资料定位最小缺口，不自行初始化整套系统。
2. 按[共享约定](../../references/shared-work.md)核对任务身份、负责人、在途工作、路线及实际候选。探索明确要回答的问题和允许的试验范围；交付明确期望行为及验证方法。已有设计直接引用，小反馈使用“当前行为→期望变化→例子”。
3. 检查可写工作区、共享接口依赖与集成目标，按项目已有机制认领。同一个人的多个 Session 也要明确各自写入范围；文件不重叠不能证明任务独立。宿主与任务平台负责执行和调度，插件不派发固定角色或固定模型。
4. 自主完成获授权的调查、实现、验证和普通修复。中途反馈、恢复或发现目标变化时，读取[变化处理](../../references/change-and-integration.md)，刷新受影响决定和外部状态；已授权的同一目标不逐步求批。
5. 形成候选交付或转交时，使用已安装的 `dev-harness-change` 作者准备模式或 `dev-harness-handoff`。若该入口未安装，按共享约定输出等价材料并说明缺口；探索结论可以没有 MR。

完成以任务结果和实际证据为准。外部平台不可用时保存本地候选与待同步内容，明确尚未共享；仅阻塞缺少真实前提的工作，业务未知不能用猜测填补。
